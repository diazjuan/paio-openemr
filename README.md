## 1. Introduction and architecture

This guide describes the complete installation of PAIO8 from scratch on a Linux server with Docker. The platform combines third-party software that is downloaded automatically as container images, plus four PAHO modules cloned from GitHub.

**Important note on where each component comes from.** You do not copy or compile OpenEMR, Jitsi, or the ICD-11 API by hand. They are all downloaded as official images, and that download is performed by Docker Compose the first time it brings up the services (step 7). Only the four PAHO modules are obtained with `git clone`.

| Component | Source | How it is obtained |
| --- | --- | --- |
| OpenEMR 8.0.0.2 | Official OpenEMR repository on GitHub, published as the image `openemr/openemr:8.0.0.2` | Docker Compose pulls the image when you run `docker compose up` |
| Database (MariaDB 11.8) | Official image `mariadb:11.8` | Docker Compose |
| Jitsi Meet (web, prosody, jicofo, jvb) | Official Jitsi images `jitsi/web`, `jitsi/prosody`, `jitsi/jicofo`, `jitsi/jvb` (stable tag) | Docker Compose pulls the images; Jitsi runs inside the containers |
| ICD-11 API (WHO) | Official WHO image `whoicd/icd-api` | Docker Compose; the ICD-11 content is provided directly by the WHO inside the image |
| PAHO modules (4) | Repositories on `github.com/diazjuan` | Cloned with `git clone` into `custom_modules/` (step 8) |

The four PAHO modules included in this installation are:

- **`paho_jitsi_televisit_module`** — Televisit with embedded Jitsi Meet and JWT authentication.
- **`paho_openemr_icd_11`** — ICD-11 (WHO) diagnosis search and recording in the patient workflow. In the OpenEMR interface the module appears as "PAHO ICD-11 Integration".
- **`paho_openemr_translations`** — Spanish translations for OpenEMR and the PAHO modules.
- **`paio_login_theme`** — Visual branding (OPS logo and colors) on the login screen.

## 2. Prerequisites

Before you begin, make sure you have the following:

- A Linux server (Ubuntu 24.x) with at least **25 GB** of free disk space.
- **Docker** and **Docker Compose** installed on the server.
- **git** installed (to clone the PAHO modules).
- **SSH** access to the server with a user that has `sudo` privileges.
- A **domain** (for example `emr.yourdomain.com`) whose DNS record points to the server's public IP.
- Firewall ports open: **80/TCP** (certificate issuance and renewal), **443/TCP** (OpenEMR), **8444/TCP** (Jitsi web), and **10000/UDP** (Jitsi/JVB media).

Verify that Docker and Docker Compose are available:

```bash
docker --version
docker compose version
```

> **Note:** This guide assumes a single domain for OpenEMR (port 443) and Jitsi (port 8444). No reverse proxy is used: each container exposes its own port.

## 3. Project structure

Connect to the server over SSH and create the working folder:

```bash
mkdir -p ~/paio8/custom_modules
cd ~/paio8
```

When the installation is complete, the structure will look like this:

```text
~/paio8/
|- .env                         <- configuration (step 5)
|- docker-compose.yml           <- service definitions (step 6)
|- jitsi-config/                <- Jitsi config (generated by the containers)
|- custom_modules/              <- PAHO modules (cloned in step 8)
|   |- paho_jitsi_televisit_module/
|   |- paho_openemr_icd_11/
|   |- paho_openemr_translations/
|   `- paio_login_theme/
```

> **Note:** The `jitsi-config/` folder is generated automatically by the Jitsi containers the first time they start; you do not need to create or edit it by hand.

## 4. SSL certificates (Let's Encrypt)

Issue the certificate before bringing up the containers, while port 80 is free. A single certificate for the domain covers both OpenEMR (443) and Jitsi (8444), because both use the same host name.

```bash
sudo apt update && sudo apt install -y certbot
sudo certbot certonly --standalone -d emr.yourdomain.com
```

The certificate and key are placed in `/etc/letsencrypt/live/emr.yourdomain.com/`. The `docker-compose.yml` in step 6 mounts those files into the OpenEMR and Jitsi containers in read-only mode.

> **Note:** Automatic renewal (`certbot renew`) needs port 80 free. Stop OpenEMR briefly during renewal, or use a deploy hook that restarts the containers after renewing.

## 5. The `.env` configuration file

Create the `.env` file in `~/paio8/`:

```bash
nano ~/paio8/.env
```

Paste the following content and replace each value for your environment. Replace `emr.yourdomain.com` with your real domain (also in step 6):

```ini
# =============================================================
# PAIO8 - OpenEMR 8.0.0.2 + Jitsi + ICD-11
# Configuration file (.env)
# =============================================================

# Public domain of the server (must resolve via DNS to the server IP)
SERVER_HOST=emr.yourdomain.com

# OpenEMR ports (80 redirects automatically to 443)
OPENEMR_PORT=80
OPENEMR_HTTPS_PORT=443

# Jitsi ports
JITSI_PORT=8444
JITSI_UDP_PORT=10000

# Database (MariaDB)
MYSQL_ROOT_PASSWORD=ChangeThisStrongPassword1
MYSQL_PASSWORD=ChangeThisStrongPassword2

# OpenEMR initial administrator
OE_USER=admin
OE_PASS=ChangeThisStrongPassword3

# Jitsi internal secrets (XMPP)
JICOFO_COMPONENT_SECRET=ChangeThisSecret1
JICOFO_AUTH_PASSWORD=ChangeThisSecret2
JVB_AUTH_PASSWORD=ChangeThisSecret3

# Jitsi JWT authentication (Televisit module)
# Generate the secret with:  openssl rand -hex 32
JWT_APP_ID=paho-jitsi-televisit
JWT_APP_SECRET=PASTE_THE_OUTPUT_OF_openssl_rand_hex_32_HERE
```

Generate the JWT secret with the command below and paste it into `JWT_APP_SECRET`:

```bash
openssl rand -hex 32
```

Save and exit nano: `Ctrl+O` → `Enter` → `Ctrl+X`.

> **Note:** The same `JWT_APP_SECRET` and `JWT_APP_ID` are injected into OpenEMR (the token issuer) and into the Jitsi containers (the verifiers). They must match exactly or the video room will reject the connection. Use a different secret per environment.

## 6. The `docker-compose.yml` file

Create the `docker-compose.yml` file in `~/paio8/`:

```bash
nano ~/paio8/docker-compose.yml
```

It defines the following 7 services. Remember these images download themselves: there is no need to copy or compile OpenEMR, Jitsi, or the ICD-11 API.

| Service | Image | Host port |
| --- | --- | --- |
| mysql | `mariadb:11.8` | internal |
| openemr | `openemr/openemr:8.0.0.2` | 80, 443 |
| jitsi-web | `jitsi/web:stable` | 8444 |
| prosody | `jitsi/prosody:stable` | internal |
| jicofo | `jitsi/jicofo:stable` | internal |
| jvb | `jitsi/jvb:stable` | 10000/UDP |
| icd11-api | `whoicd/icd-api:latest` | internal |

Paste the full content (replace `emr.yourdomain.com` with your domain in the four certificate paths):

```yaml
services:
  mysql:
    image: mariadb:11.8
    container_name: paio_mysql
    restart: unless-stopped
    command:
      - mariadbd
      - --character-set-server=utf8mb4
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "/usr/local/bin/healthcheck.sh", "--su-mysql", "--connect", "--innodb_initialized"]
      start_period: 1m
      start_interval: 10s
      interval: 1m
      timeout: 5s
      retries: 3
    networks:
      - paio_network

  openemr:
    image: openemr/openemr:8.0.0.2
    container_name: paio_openemr
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "${OPENEMR_PORT}:80"
      - "${OPENEMR_HTTPS_PORT}:443"
    environment:
      MYSQL_HOST: mysql
      MYSQL_ROOT_PASS: ${MYSQL_ROOT_PASSWORD}
      MYSQL_USER: openemr
      MYSQL_PASS: ${MYSQL_PASSWORD}
      OE_USER: ${OE_USER}
      OE_PASS: ${OE_PASS}
      # Jitsi JWT signing material (issuer side). The Televisit module
      # reads it env-first; DB globals are the fallback.
      JWT_APP_ID: ${JWT_APP_ID}
      JWT_APP_SECRET: ${JWT_APP_SECRET}
    volumes:
      - openemr_logs:/var/log
      - openemr_sites:/var/www/localhost/htdocs/openemr/sites
      # PAHO modules (cloned in step 8)
      - ./custom_modules:/var/www/localhost/htdocs/openemr/interface/modules/custom_modules
      # Production TLS certificates (Let's Encrypt)
      - /etc/letsencrypt/live/emr.yourdomain.com/fullchain.pem:/etc/ssl/certs/webserver.cert.pem:ro
      - /etc/letsencrypt/live/emr.yourdomain.com/privkey.pem:/etc/ssl/private/webserver.key.pem:ro
    healthcheck:
      test: ["CMD", "/usr/bin/curl", "--fail", "--insecure", "--location", "--show-error", "--silent", "https://localhost/meta/health/readyz"]
      start_period: 3m
      start_interval: 10s
      interval: 1m
      timeout: 5s
      retries: 3
    networks:
      - paio_network

  jitsi-web:
    image: jitsi/web:stable
    container_name: paio_jitsi_web
    restart: unless-stopped
    ports:
      - "${JITSI_PORT}:443"
    environment:
      TZ: America/Chicago
      PUBLIC_URL: https://${SERVER_HOST}:${JITSI_PORT}
      DISABLE_HTTPS: "0"
      XMPP_SERVER: prosody
      XMPP_DOMAIN: meet.jitsi
      XMPP_AUTH_DOMAIN: auth.meet.jitsi
      XMPP_GUEST_DOMAIN: guest.meet.jitsi
      XMPP_MUC_DOMAIN: muc.meet.jitsi
      XMPP_INTERNAL_MUC_DOMAIN: internal-muc.meet.jitsi
      XMPP_BOSH_URL_BASE: http://prosody:5280
      # Only valid JWTs may join the room.
      ENABLE_AUTH: "1"
      ENABLE_GUESTS: "0"
      AUTH_TYPE: jwt
      JWT_APP_ID: ${JWT_APP_ID}
      JWT_APP_SECRET: ${JWT_APP_SECRET}
      ENABLE_XMPP_WEBSOCKET: "1"
      ENABLE_PREJOIN_PAGE: "1"
      ENABLE_WELCOME_PAGE: "1"
      ENABLE_P2P: "1"
      JVB_PORT: "10000"
      JVB_TCP_HARVESTER_DISABLED: "true"
    volumes:
      - ./jitsi-config/web:/config
      - ./jitsi-config/web/crontabs:/var/spool/cron/crontabs
      - ./jitsi-config/transcripts:/usr/share/jitsi-meet/transcripts
      # The Jitsi container reuses the same domain certificate
      - /etc/letsencrypt/live/emr.yourdomain.com/fullchain.pem:/config/keys/cert.crt:ro
      - /etc/letsencrypt/live/emr.yourdomain.com/privkey.pem:/config/keys/cert.key:ro
    depends_on:
      - prosody
      - jvb
    networks:
      - paio_network

  prosody:
    image: jitsi/prosody:stable
    container_name: paio_jitsi_prosody
    restart: unless-stopped
    expose:
      - "5222"
      - "5280"
      - "5347"
    environment:
      TZ: America/Chicago
      PUBLIC_URL: https://${SERVER_HOST}:${JITSI_PORT}
      XMPP_DOMAIN: meet.jitsi
      XMPP_AUTH_DOMAIN: auth.meet.jitsi
      XMPP_GUEST_DOMAIN: guest.meet.jitsi
      XMPP_MUC_DOMAIN: muc.meet.jitsi
      XMPP_INTERNAL_MUC_DOMAIN: internal-muc.meet.jitsi
      XMPP_RECORDER_DOMAIN: recorder.meet.jitsi
      AUTH_TYPE: jwt
      ENABLE_AUTH: "1"
      ENABLE_GUESTS: "0"
      ENABLE_LOBBY: "0"
      JWT_APP_ID: ${JWT_APP_ID}
      JWT_APP_SECRET: ${JWT_APP_SECRET}
      ENABLE_XMPP_WEBSOCKET: "1"
      JICOFO_AUTH_USER: focus
      JICOFO_AUTH_PASSWORD: ${JICOFO_AUTH_PASSWORD}
      JICOFO_COMPONENT_SECRET: ${JICOFO_COMPONENT_SECRET}
      JVB_AUTH_USER: jvb
      JVB_AUTH_PASSWORD: ${JVB_AUTH_PASSWORD}
      LOG_LEVEL: info
    volumes:
      - ./jitsi-config/prosody/config:/config
      - ./jitsi-config/prosody/prosody-plugins-custom:/prosody-plugins-custom
    networks:
      paio_network:
        aliases:
          - xmpp.meet.jitsi

  jicofo:
    image: jitsi/jicofo:stable
    container_name: paio_jitsi_jicofo
    restart: unless-stopped
    environment:
      TZ: America/Chicago
      XMPP_SERVER: prosody
      XMPP_DOMAIN: meet.jitsi
      XMPP_AUTH_DOMAIN: auth.meet.jitsi
      XMPP_INTERNAL_MUC_DOMAIN: internal-muc.meet.jitsi
      XMPP_MUC_DOMAIN: muc.meet.jitsi
      JICOFO_AUTH_USER: focus
      JICOFO_AUTH_PASSWORD: ${JICOFO_AUTH_PASSWORD}
      JICOFO_COMPONENT_SECRET: ${JICOFO_COMPONENT_SECRET}
      JVB_BREWERY_MUC: jvbbrewery
      ENABLE_AUTH: "0"
    volumes:
      - ./jitsi-config/jicofo:/config
    depends_on:
      - prosody
    networks:
      - paio_network

  jvb:
    image: jitsi/jvb:stable
    container_name: paio_jitsi_jvb
    restart: unless-stopped
    ports:
      - "${JITSI_UDP_PORT}:10000/udp"
    environment:
      TZ: America/Chicago
      PUBLIC_URL: https://${SERVER_HOST}:${JITSI_PORT}
      XMPP_SERVER: prosody
      XMPP_DOMAIN: meet.jitsi
      XMPP_AUTH_DOMAIN: auth.meet.jitsi
      XMPP_INTERNAL_MUC_DOMAIN: internal-muc.meet.jitsi
      JVB_AUTH_USER: jvb
      JVB_AUTH_PASSWORD: ${JVB_AUTH_PASSWORD}
      JVB_BREWERY_MUC: jvbbrewery
      JVB_PORT: "10000"
      JVB_TCP_HARVESTER_DISABLED: "true"
      DOCKER_HOST_ADDRESS: ${SERVER_HOST}
    volumes:
      - ./jitsi-config/jvb:/config
    depends_on:
      - prosody
    networks:
      - paio_network

  icd11-api:
    image: whoicd/icd-api:latest
    container_name: paio_icd11_api
    restart: unless-stopped
    environment:
      acceptLicense: "true"
      saveAnalytics: "false"
      include: "2026-01_en-es-pt"
    expose:
      - "80"
    networks:
      paio_network:
        aliases:
          - icd11-api

volumes:
  mysql_data:
  openemr_sites:
  openemr_logs:

networks:
  paio_network:
    driver: bridge
```

Save and exit: `Ctrl+O` → `Enter` → `Ctrl+X`.

## 7. Start the containers

### 7.1 Bring up all services

```bash
cd ~/paio8
docker compose up -d
```

> **Note:** The first time can take several minutes while Docker downloads the OpenEMR, Jitsi, MariaDB, and WHO ICD-11 API images. Downloading the ICD-11 content may take longer than the rest.

### 7.2 Verify the containers

```bash
docker compose ps
```

All 7 containers should show status **Up**: `paio_mysql`, `paio_openemr`, `paio_jitsi_web`, `paio_jitsi_prosody`, `paio_jitsi_jicofo`, `paio_jitsi_jvb`, and `paio_icd11_api`.

### 7.3 Monitor the OpenEMR initial setup

```bash
docker compose logs -f openemr
```

Wait until you see the line:

```text
Setup Complete!
```

> **Note:** Do not open the browser until that line appears. Exit the log with `Ctrl+C`.

### 7.4 Verify access

Open OpenEMR in your browser:

```text
https://emr.yourdomain.com
```

You should see the OpenEMR login page. Sign in with the user and password set in `.env` (`OE_USER` / `OE_PASS`).

Also verify that Jitsi responds:

```text
https://emr.yourdomain.com:8444
```

## 8. Clone the PAHO modules

The four modules are cloned from `github.com/diazjuan` into the `custom_modules/` folder, which is mounted into the OpenEMR container. First take ownership of the folder:

```bash
sudo chown -R $USER:$(id -gn) ~/paio8/custom_modules
cd ~/paio8/custom_modules
```

Clone the four repositories (each creates its own folder named after the repository):

```bash
git clone https://github.com/diazjuan/paho_jitsi_televisit_module.git
git clone https://github.com/diazjuan/paho_openemr_icd_11.git
git clone https://github.com/diazjuan/paho_openemr_translations.git
git clone https://github.com/diazjuan/paio_login_theme.git
```

> **Note:** Keep the names exactly as shown: the login theme module is `paio_login_theme` (with **paio**, not paho).

Restart OpenEMR so it detects the newly cloned modules:

```bash
cd ~/paio8 && docker compose restart openemr
```

Wait about 30 seconds before continuing.

## 9. Register, install, and enable the modules

Sign in to OpenEMR as an administrator and go to **Modules → Manage Modules**. The four modules will appear under **Unregistered**. For each one, in this order:

1. Click **Register**.
2. Click **Install**.
3. Click **Enable**.

Do the three steps for all four modules:

- PAHO Jitsi Televisit
- PAHO ICD-11 Integration
- PAIO Translations
- PAHO OPS Login Theme

> **Note:** Once enabled, each module shows a **Configure** button (gear icon) on its row. Module-specific configuration is covered in step 10.

## 10. Configure each module

### 10.1 Televisit (`paho_jitsi_televisit_module`)

In **Manage Modules**, open **Configure** on the PAHO Jitsi Televisit row and set:

- **Jitsi Base URL:** `https://emr.yourdomain.com:8444`
- **Televisit Category:** select the calendar category that identifies televisit appointments (see step 11).
- **Room Naming Strategy:** leave **Deterministic** (the same appointment always gets the same room).

In the **JWT Authentication** section the status must be green: *"Token authentication is configured"*, with source **environment**. This confirms that the `JWT_APP_SECRET` from the `.env` file reached the container correctly.

Click **Save Configuration**.

> **Note:** The JWT secret and App ID are read from the environment (`.env`) and shown read-only; they are not edited from this screen.

### 10.2 ICD-11 (`paho_openemr_icd_11`)

Open **Configure** on the PAHO ICD-11 Integration row. The default values already work with the API that Docker Compose started; just verify they match:

| Setting | Value | Note |
| --- | --- | --- |
| ICD-11 API base URL | `http://icd11-api` | Internal Docker URL; never exposed to the browser. |
| ICD-11 release | `2026-01` | Must be loaded in the API container (the `include` key in the compose). |
| Linearization | `mms` | Clinical linearization. |
| Default language | `es` | Fallback when the interface language does not map to `en`, `es`, or `pt`. |

If the values are correct, save. The module queries the WHO ICD-11 API running in the `paio_icd11_api` container, reachable only inside the Docker network.

### 10.3 Translations (`paho_openemr_translations`)

Open **Configure** on the PAIO Translations row and click **Run**. The page reports the `lang_constants` / `lang_definitions` row counts before and after, plus the duration.

> **Note:** The translation script is idempotent: you can run it multiple times safely. The module does not create automatic backups; if you want to be able to roll back, take a `mysqldump` of `lang_constants` and `lang_definitions` before running it.

Clear the cache and restart OpenEMR so the language is applied across the whole interface:

```bash
docker exec paio_openemr rm -rf /tmp/php-file-cache/*
cd ~/paio8 && docker compose restart openemr
```

### 10.4 Login theme (`paio_login_theme`)

This module needs no configuration: once enabled, the login screen already shows the OPS logo and colors. Open the login page in a private window to confirm it.

Each site can also add its own logo without touching code:

1. **Administration → Logos:** upload your logo as the **Secondary Login Logo** (`core/login/secondary`).
2. **Administration → Globals → Appearance:** enable the secondary login logo.
3. The site logo appears below the OPS logo.

## 11. OpenEMR initial setup

Before creating the first Televisit, complete the basic configuration in this order:

| Step | Location | What to configure |
| --- | --- | --- |
| 1 | Admin → Config → Locale | Language, time zone, date format |
| 2 | Admin → Config → Portal | Enable the patient portal and its URL |
| 3 | Admin → Clinic → Facilities | Clinic name and details |
| 4 | Admin → Users | Provider: name, username, password, Provider role |
| 5 | Patient → New/Search | Patient: details, email, and portal access |
| 6 | Calendar → Categories | Create/identify the 'Televisit' category (linked in step 10.1) |
| 7 | Calendar → click a time slot | Appointment: 'Televisit' category, patient, and provider |

## 12. Televisit workflow

### Provider workflow

1. Open the Calendar in OpenEMR and click the Televisit appointment.
2. In the "Televisit" panel, click "Open Unified Televisit View".
3. The view opens with the Jitsi video and the encounter form.
4. Click "Open Video Conference" to start the session.
5. Document the encounter in the form during the consultation.

### Patient workflow (Portal)

1. The patient opens the portal: `https://emr.yourdomain.com/portal`.
2. Signs in with their credentials.
3. Goes to Appointments and finds the one marked "Televisit".
4. Clicks "Join Televisit".

> **Note:** Room access is protected by JWT: both the provider and the patient enter with a signed token issued by OpenEMR. Nobody without a valid token can join the room.

## 13. Maintenance and module updates

To update a module to the latest version published on `github.com/diazjuan`, enter its folder and run `git pull`; then restart OpenEMR:

```bash
cd ~/paio8/custom_modules/paho_jitsi_televisit_module && git pull
cd ~/paio8 && docker compose restart openemr
```

> **Note:** Repeat `git pull` in the folder of whichever module you want to update. If an update includes schema changes, return to Manage Modules and follow the Module Manager's upgrade prompt.
